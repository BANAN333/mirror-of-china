# Инструкции для MVP «Зеркало Поднебесной»

## Инструкция по установке

Опубликованный MVP открывается в браузере без установки и регистрации. Для локальной сборки понадобятся Git и Python 3.13. Эту версию Python использует и публикация на GitHub Pages.

```powershell
git clone https://github.com/BANAN333/mirror-of-china.git
cd mirror-of-china
python scripts/validate_faq.py
python scripts/build_site.py
python -m http.server 8000 --directory site
```

Если команда `python` недоступна, используйте `py -3.13` на Windows или `python3` на macOS и Linux. Откройте [локальный сайт](http://localhost:8000/). Чтобы остановить сервер, нажмите Ctrl+C.

## Руководство пользователя

1. Откройте китайскую версию сайта. Кнопка «Русский» переключает язык.
2. В разделе `全部问答` («Все вопросы и ответы») выберите тему или введите ключевое слово, например `护照` («паспорт»). Под ответом указаны официальный источник и дата проверки.
3. В разделе `申请助手` («Помощник по поступлению») укажите форму обучения, способ поступления, уровень программы, имеющееся образование и знание русского языка. Найдите программу по коду или названию. Можно выбрать вторую программу для сравнения или сформировать план без выбора программы.
4. Откройте `行动计划` («План действий»). Отмечайте выполненные задачи и сверяйте условия и сроки по ссылкам на официальные материалы РУТ (МИИТ).

[Китайская версия сайта](https://banan333.github.io/mirror-of-china/zh/) · [Помощник по поступлению](https://banan333.github.io/mirror-of-china/zh/guides/index.html)

## Руководство администратора

1. Сверьте обновлённые сведения с официальным источником РУТ (МИИТ) и внесите изменения в `data/ru/faq.json` и `data/zh/faq.json`. У двух языковых версий одной записи должен совпадать идентификатор.
2. Укажите актуальную ссылку и дату проверки. После проверки фактов и перевода установите статус `verified`. Сборка включает в публичный FAQ записи с этим статусом.
3. Запустите `python scripts/validate_faq.py`, затем `python scripts/build_site.py`. Проверьте изменённый ответ и ссылку на источник в обеих языковых версиях.
4. Сохраните изменения в Git. При попадании изменений в `main` GitHub Actions запускает валидацию и сборку, затем публикует каталог `site/` на GitHub Pages. После успешной публикации проверьте обновлённый ответ на рабочем сайте.
